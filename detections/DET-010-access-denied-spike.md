# DET-010 – AccessDenied Spike from Single Identity

## Overview
Detects a high volume of AccessDenied errors from a single IAM identity
in a short time window. Indicates enumeration or privilege testing by
a low-privilege user or compromised credential.

## Why This Matters
When an attacker gains access to a low-privilege credential they will
typically attempt to enumerate what they have access to by calling
various AWS APIs and observing what succeeds or fails. This produces
a burst of AccessDenied events across multiple services in a short
window — a pattern that almost never occurs in normal legitimate usage.
A single user hitting AccessDenied across IAM, S3, EC2, and CloudTrail
in the same session is a strong signal of credential-based reconnaissance.

## CloudTrail Event
- **Event Name:** Any (filter on errorCode)
- **errorCode:** AccessDenied or Client.UnauthorizedOperation
- **Read Only:** true and false

## Key Fields to Inspect
| Field | Value |
|---|---|
| errorCode | AccessDenied, UnauthorizedOperation |
| userIdentity.arn | Identity generating the errors |
| eventName | Which actions were attempted |
| eventSource | Which services were probed |
| eventTime | Cluster within short window = suspicious |

## Detection Logic (Pseudocode)
```sql
WHERE errorCode IN ("AccessDenied", "Client.UnauthorizedOperation")
GROUP BY userIdentity.arn, window(5 minutes)
ALERT MEDIUM if count >= 3 distinct eventSources
ALERT HIGH if count >= 5 distinct eventSources
-- Enrich: is this identity newly created?
-- Enrich: does this identity have any successful calls in same window?
```

## Evidence
Real CloudTrail events captured from lab environment.
All generated by analyst-user, a zero-permission IAM user.

| Action Attempted | Service | Error |
|---|---|---|
| ListBuckets | S3 | AccessDenied |
| ListUsers | IAM | AccessDenied |
| DescribeTrails | CloudTrail | AccessDeniedException |
| DescribeInstances | EC2 | UnauthorizedOperation |
| ListRoles | IAM | AccessDenied |

- Evidence file: evidence/access-denied.json

## Notes
Five AccessDenied events across four different AWS services in a single
session from a user with no legitimate business reason to call any of
these APIs. In a real environment this pattern — especially spanning
IAM, S3, EC2, and CloudTrail — maps directly to the reconnaissance
phase of an AWS attack chain. The combination of services probed
suggests the attacker was attempting to understand the environment
before escalating.
